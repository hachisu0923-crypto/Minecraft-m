## 主要ファイルの責務

### gradle.properties — 単一の真実
全バージョン（`minecraft_version` / `forge_version` / `mapping_*`）と
mod メタデータ（`mod_id` / `mod_name` / `mod_version` / `mod_group_id` / `mod_authors` / `mod_description`）。
**ここを変えれば mods.toml にも反映される**（build.gradle の `processResources` が `${...}` を置換）。

### build.gradle
- ForgeGradle 6.0 プラグイン適用
- Java toolchain を **17 に固定**（変更禁止）
- `minecraft { mappings ... runs { client/server/data } }`
- `processResources` で `mods.toml` / `pack.mcmeta` のトークン置換
- `jar` の manifest 設定 + `reobfJar`

### mods.toml
Forge が Mod を認識するための必須メタデータ。`modId` は `@Mod` と完全一致。
`${...}` は **生のまま**正しい（ビルド時に置換される）。手で値を埋めない。

### pack.mcmeta
リソース/データパック形式の宣言。1.20.1 は `pack_format = 15`。

### ExampleMod.java（エントリポイント）
`@Mod(MOD_ID)` が付いたクラス。コンストラクタで Mod イベントバスを取得し、
各 `DeferredRegister` を `register(modEventBus)` で接続する。
**新しい登録クラスを足したら、ここで register を呼ぶのを忘れない。**

### registry/*.java
`DeferredRegister` + `RegistryObject` で要素を宣言。
新要素を足すときの **コピー元テンプレート**。`docs/04` `docs/05` 参照。

### entity/ ・ client/ ・ command/（エンティティ実例）
- `entity/Singularity.java` — ボス本体。エンティティは登録だけでなく
  **属性を `EntityAttributeCreationEvent`（MOD バス）** で登録する点に注意（`docs/03`）。
- `client/` — レンダラは **`EntityRenderersEvent.RegisterRenderers`（MOD バス・
  クライアント専用）** で登録。サーバ経路から client クラスを参照しない。
- `command/` — ゲーム中コマンドは **Forge バス**の `RegisterCommandsEvent`。
- 設計と Epic Fight 連携の詳細は `docs/12-EpicFight特異点ボス.md`。

## 命名規約

- mod id / フォルダ名: 小文字英数字と `_`
- レジストリ名（`register("...")`）: `snake_case`
- Java クラス: `PascalCase`、定数: `UPPER_SNAKE_CASE`
- lang キー: `item.<modid>.<name>` / `block.<modid>.<name>` /
  `entity.<modid>.<name>` / `itemGroup.<modid>.<tab>`
- リソース参照の名前空間: `<modid>:path`（例 `examplemod:item/example_item`）
