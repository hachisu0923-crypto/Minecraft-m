# 09 - 機能追加ワークフロー（汎用レシピ）

何を追加する場合でも使う共通手順。自律エージェントはまずこれを開く。

## 手順（毎回この順）

### STEP 0 — 種別を判定
追加物が何かで参照先を決める:

| 追加物 | 主参照 | コピー元 |
|---|---|---|
| アイテム | `docs/04` | `registry/ModItems.java` |
| ブロック | `docs/05` | `registry/ModBlocks.java` |
| クリエイティブタブ要素 | `docs/04`/`05` の §タブ | `registry/ModCreativeTabs.java` |
| エンティティ（mob/ボス） | `docs/03` §エンティティ + `docs/epicfight/12` | `registry/ModEntities.java` + `entity/Singularity.java` |
| その他新カテゴリ（音/エンチャ等） | `docs/03` §DeferredRegister | `registry/ModItems.java` を雛形に新クラス |
| レシピ/タグ/loot のみ | `docs/06` | 既存 JSON |

### STEP 1 — 登録コード
- 既存 `registry/ModXxx.java` に `RegistryObject` を追加（コピー＆改名）
- 新カテゴリなら新 `ModXxx.java` を作り、`ExampleMod` コンストラクタに
  `ModXxx.REGISTER.register(modEventBus);` を**必ず追加**
- レジストリ名は `snake_case`。以降すべてこの名前で統一

### STEP 2 — アセット/データを過不足なく
種別ごとの必須セット（欠けると紫黒/無音）:

- **アイテム**: `models/item/<n>.json` + `textures/item/<n>.png` + lang(en_us & ja_jp)
- **ブロック**: blockstate + `models/block/<n>.json` + `models/item/<n>.json`
  + `textures/block/<n>.png` + `loot_tables/blocks/<n>.json` + lang(en_us & ja_jp)
- **エンティティ**: EntityType 登録 + 属性(`EntityAttributeCreationEvent`)
  + レンダラ(`RegisterRenderers`) + `textures/entity/<n>.png`
  + lang `entity.examplemod.<n>`(en_us & ja_jp) + （任意）スポーンエッグ。詳細 `docs/03`/`docs/epicfight/12`

パス規約は `docs/06`。名前空間は常に `examplemod:`。lang は en_us と ja_jp の**両方**。

### STEP 3 — 表示導線
クリエイティブタブで触れるよう `ModCreativeTabs.java` の `displayItems` に
`output.accept(...)` を追加（テスト容易性のため推奨）。

### STEP 4 — 検証（順番厳守）
```bash
# (a) JSON 全件パース
for f in $(find src -name '*.json'); do
  python3 -m json.tool "$f" >/dev/null 2>&1 || echo "BAD JSON: $f"; done
# (b) mod id 一貫性
grep -n modId src/main/resources/META-INF/mods.toml
# (c) wrapper
./gradlew --version            # Gradle 8.1.1
# (d) ネットワーク開放なら
./gradlew build                # BUILD SUCCESSFUL
# (e) GUI 環境なら手動確認
./gradlew runClient            # 追加物がタブに出るか / エンティティはスポーンエッグや /summon で確認
```

### STEP 5 — 報告
- 何を追加したか（登録名・ファイル一覧）
- どこまで検証できたか（(a)(b)(c) は常時可、(d)(e) は環境依存）
- 検証できていない項目は「未検証」と明記。憶測で「動作確認済」と書かない

### STEP 6 — コミット/push
- ブランチ `claude/minecraft-mod-docs-Wkrcu` に commit
- `git push -u origin claude/minecraft-mod-docs-Wkrcu`
  （ネットワーク失敗時のみ指数バックオフ 2/4/8/16s、最大4回）
- PR はユーザーが明示要求したときだけ

## 判断に迷ったら

- 仕様が曖昧／大規模リファクタが必要／アーキテクチャに影響 → **進めず確認する**
- 小さく追加して都度 STEP 4 で検証 → 失敗の原因を局所化できる
- 既存の `registry/*.java` と JSON を**コピー元**にする（ゼロから書かない）
