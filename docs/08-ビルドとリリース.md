# 08 - ビルドとリリース

## ビルド

```bash
./gradlew build
```

成果物: `build/libs/examplemod-<mod_version>.jar`
（`<mod_version>` は `gradle.properties` の `mod_version`。例: `examplemod-1.0.0.jar`）

- このファイルが配布用 Mod 本体。`mods/` フォルダに入れて動く
- `build/libs/` に `*-sources.jar` 等が出ることがある。配布するのは無印 jar
- `reobfJar`（`jar` の finalizedBy）で本番マッピングへ再難読化される。手動操作は不要

## バージョニング

`gradle.properties` の `mod_version` を更新する（**ここだけ**変えれば jar 名にも反映）。

- 推奨: セマンティックバージョニング `MAJOR.MINOR.PATCH`
- Minecraft/Forge を上げたら `minecraft_version` / `forge_version` / `*_range` も整合させる
- `mods.toml` はトークン参照なので手修正不要

## リリース前チェック

- [ ] `gradle.properties` の `mod_version` を更新した
- [ ] `mod_license` を実際のライセンスにした（既定 All Rights Reserved のまま配布しない）
- [ ] `mod_authors` / `mod_description` を実態に合わせた
- [ ] JSON 全件パス（`docs/07`）
- [ ] （開放環境）`./gradlew clean build` が `BUILD SUCCESSFUL`
- [ ] （可能なら）`./gradlew runClient` で実機に登録物が出る
- [ ] `build/` `run/` 等をコミットしていない（`.gitignore` 済み）

## 配布形態

- 単一 jar をそのまま配布（CurseForge / Modrinth / 直接）
- 依存 Mod がある場合は `mods.toml` の `[[dependencies.examplemod]]` に追記し、利用者に明示
- ライブラリを内包したい場合のみ jarJar を検討（通常は不要。複雑さを増やさない）

## クリーンビルド

挙動が怪しいときは:
```bash
./gradlew clean
./gradlew build --refresh-dependencies
```

## 補足: 環境依存

`./gradlew build` は `maven.minecraftforge.net` 等への到達が前提。
遮断環境では完了しない（`docs/07`）。CI/開放環境でリリースビルドを行うこと。
