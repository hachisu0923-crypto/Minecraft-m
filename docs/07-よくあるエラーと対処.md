# 07 - よくあるエラーと対処

本書は「症状 → 原因」の早見表。表で解決しない／再現が不安定なときは
**`docs/10-バグとエラー対応.md`（切り分け・調査・修正・報告の手順書）**へ。

## 検証コマンド（変更後に毎回）

```bash
# 1. JSON 全件パース
for f in $(find src -name '*.json'); do
  python3 -m json.tool "$f" >/dev/null 2>&1 || echo "BAD JSON: $f"
done

# 2. mod id 一貫性（出力がすべて examplemod か）
grep -n 'modId' src/main/resources/META-INF/mods.toml
ls src/main/resources/assets src/main/resources/data

# 3. wrapper（Gradle 8.1.1 表示で OK）
./gradlew --version

# 4. ネットワーク開放確認（403/000 なら遮断）
curl -s -o /dev/null -w "%{http_code}\n" \
  https://maven.minecraftforge.net/net/minecraftforge/forge/maven-metadata.xml
```

## エラー早見表

### ビルド系

| 症状 | 原因 | 対処 |
|---|---|---|
| `Plugin [id: 'net.minecraftforge.gradle'] was not found` | プラグインリポジトリ未到達 | `settings.gradle` の pluginManagement を確認。ネットワーク遮断なら `docs/01` §初回ビルド |
| `Could not resolve net.minecraftforge:forge:...` | `maven.minecraftforge.net` 遮断 or バージョン誤り | ネットワーク開放を確認。`gradle.properties` の `forge_version`（既定 47.4.10）を確認 |
| `Unsupported class file major version` / toolchain エラー | JDK が 17 でない/見つからない | JDK17 を導入。`./gradlew -q javaToolchains` で確認（`docs/01`） |
| `Could not determine java version` | Gradle と JDK の組合せ不正 | wrapper は 8.1.1 固定。実行 JDK を確認 |
| 依存が壊れている/古い | キャッシュ不整合 | `./gradlew build --refresh-dependencies` |
| Gradle distribution が落ちてこない | `services.gradle.org` 遮断 | ネットワークポリシーを確認 |

### 実行・表示系

| 症状 | 原因 | 対処 |
|---|---|---|
| アイテム/ブロックが紫黒（missing texture） | モデル JSON かテクスチャの名前/パス不一致 | `docs/04`/`docs/05` のチェックリスト。名前空間は `examplemod:` |
| 名前が `item.examplemod.xxx` のまま | lang キー誤り or ファイル未追加 | `lang/en_us.json` と `ja_jp.json` の両方を確認 |
| Mod が一覧に出ない | `mods.toml` の `modId` ≠ `@Mod` 引数 | 両者を完全一致させる（`docs/02`） |
| 起動時クラッシュ `Registry object not present` | クラスロード時に `RegistryObject.get()` を呼んだ | `.get()` は使用時のみ。フィールド初期化で呼ばない |
| ブロックを壊しても何も出ない | loot_table 不足/名前不一致 | `data/examplemod/loot_tables/blocks/<name>.json`（`docs/05`） |
| `runClient` が起動しない（headless） | GUI/ディスプレイなし環境 | headless では client 起動不可。`build` まで検証し、その旨報告 |

### JSON / メタデータ系

| 症状 | 原因 | 対処 |
|---|---|---|
| `JsonSyntaxException` | 末尾カンマ・閉じ括弧漏れ・全角引用符 | 検証コマンド 1 で特定。半角 `"` を使う |
| `mods.toml` に `${mod_id}` が残る | これは正常（ビルド前の生ファイル） | `processResources` が置換。手で埋めない |
| `pack_format` 関連の警告 | 値が 1.20.1 用でない | `pack.mcmeta` は `15` 固定 |

## 切り分けの基本

1. まず検証コマンド 1〜2（JSON / id 一貫性）— ネットワーク不要、ほぼここで判明
2. `./gradlew --version`（wrapper 健全性）
3. ネットワーク開放確認（コマンド 4）
4. 開放なら `./gradlew build --stacktrace`、遮断なら静的検証までで報告

**遮断環境ではビルド不可は異常ではない。** 「静的検証は通った／ビルドはネットワーク遮断で未実施」と
正直に切り分けて報告する（`CLAUDE.md` §4）。
